# ADR-005. 단일 가용영역에 배포하되 코드는 확장 가능하게 한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `NFR-05`, `C-04`, `F8` |

---

## 맥락

원본은 모든 리소스를 단일 가용영역에 배치했고 이중화 설계가 없었다.

## 결정

**가용영역 하나에 배포하되, 가용영역 수를 변수로 받아 확장 가능한 구조로 코드를 작성한다.**
CIDR은 가용영역별 블록을 먼저 배정하고 그 안에서 용도별로 분할한다.

## 근거

- 가용성 이중화는 요구사항이 아니다(`NFR-05`). 랩 환경이며 재생성으로 복구 가능하다(`NFR-02`).
- 비용 제약(`C-04`)상 다중 가용영역 배포는 부담이다. 관리형 방화벽은 **가용영역마다 엔드포인트가 필요**하다.
- 다만 "이중화를 몰라서 안 한 것"과 구분되어야 한다.

## 고려한 대안

**용도 우선 CIDR 배정** — 원본 방식. 서브넷마다 대역을 순서대로 할당한다. 가용영역을 추가할 때 남는 대역에 끼워 넣게 되어 규칙성이 사라진다.

## 결과

- 가용영역 장애 시 서비스가 중단된다. 랩 환경이므로 수용한다.
- 확장 시 **변수 하나 변경으로 동일 구조가 생성**된다.
- 고객 환경에서 이중화가 요구되면 무엇이 달라지는지 설명할 수 있다 — 엔드포인트 수, NAT 게이트웨이 수, 그에 따른 비용.
