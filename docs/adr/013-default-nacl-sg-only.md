# ADR-013. 네트워크 ACL은 기본값을 유지하고 접근 통제를 보안그룹으로 일원화한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `SR-04`, `F9`, `FR-07` |

---

## 맥락

서브넷 단위 접근 통제 계층을 별도로 정의할지 결정해야 한다. 원본은 공격자 주소 차단에 기본 네트워크 ACL을 수동 편집했다(`F9`).

## 결정

**기본 네트워크 ACL(전체 허용)을 유지하고, 접근 통제는 보안그룹으로 일원화한다.**

## 근거

- 네트워크 ACL은 **무상태**라 응답 트래픽용 규칙을 별도로 작성해야 하며, 임시 포트 대역을 열어야 해 실질적 통제력이 떨어진다.
- 규칙 수에 제한이 있어 세밀한 통제에 부적합하다.
- 보안그룹은 인스턴스 단위로 적용되고 **다른 보안그룹을 출발지로 참조**할 수 있어(`SR-04`) 더 정밀하다.
- 실무에서도 대부분 이 방식을 사용한다.

## 고려한 대안

**서브넷별 네트워크 ACL 정의** — 다층 방어 계층을 하나 더 확보하고 문서상 설명이 좋아진다. 그러나 무상태 특성으로 규칙이 복잡해지고 장애 시 원인 파악이 어려워진다.

## 결과

- 서브넷 단위 광역 차단 수단이 없다. 보안그룹에는 **거부 규칙이 없으므로** 특정 주소를 명시적으로 차단할 수 없다.
- **`F9`는 `FR-07`(자동 차단)로 해소한다.** 네트워크 ACL 수동 편집으로 되돌아가는 것은 원본의 문제를 반복하는 것이다.
- **`FR-07`은 선택 요구사항이므로, 미구현 시 `F9`는 미해결로 남는다.** 그 사실을 최종 문서에 명시한다.
