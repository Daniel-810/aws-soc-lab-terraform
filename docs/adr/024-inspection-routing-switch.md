# ADR-024. 검사 경로 전환은 별도 값으로 켜고 끄며, 방화벽 생성과 나눠 적용한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-25 |
| 관련 | `FR-02`, `FR-10`, `NFR-02`, `NFR-05`, `ADR-009`, `ADR-015` |

---

## 맥락

관리형 방화벽을 트래픽 경로에 넣으려면 라우팅 세 곳을 바꿔야 한다. 웹 방화벽 서브넷과 NAT 서브넷의 기본 경로를 방화벽 엔드포인트로 돌리고, 인터넷 게이트웨이에 라우팅 테이블을 연결(엣지 연결)해 들어오는 트래픽도 같은 엔드포인트를 지나게 한다. 상태 저장 검사는 연결 단위로 판단하므로 요청과 응답이 같은 엔드포인트를 지나야 한다.

`ADR-015`는 세션 관리자 접속이 NAT를 거쳐 나가므로, 방화벽이 443을 막으면 관리 접근이 끊기고 라우팅을 되돌리는 것 외에는 복구 수단이 없다고 경고했다. 방화벽 생성과 경로 전환을 한 번에 적용하면 문제가 생겼을 때 원인이 정책인지 경로인지 구분할 수 없고, 접근이 끊긴 상태에서는 확인할 방법도 사라진다.

또한 방화벽은 네트워크 모듈이 만든 서브넷에 생성되고, 네트워크 모듈의 경로는 방화벽이 만든 엔드포인트를 타깃으로 쓴다. 두 모듈이 서로의 출력을 입력으로 받는 구조가 된다.

## 결정

**네트워크 모듈에 경로 전환 여부(`inspection_enabled`)와 엔드포인트 식별자(`inspection_endpoint_id`)를 별도 입력으로 둔다.** 루트 구성은 `route_through_firewall` 변수(기본값 `false`)로 이 값을 정한다.

- 꺼져 있으면 기존 경로(인터넷 게이트웨이)를 유지한다.
- 켜지면 두 기본 경로의 타깃을 엔드포인트로 바꾸고, 엣지 연결 라우팅 테이블과 들어오는 경로(웹 방화벽 서브넷, NAT 서브넷)를 생성한다.
- 적용은 두 단계로 나눈다. 먼저 꺼진 상태로 방화벽까지 만들고 관리 접근을 확인한 뒤, 켠 상태로 다시 적용한다.

엣지 연결 라우팅 테이블도 네트워크 모듈 안에 둔다.

## 근거

- **리소스 개수는 계획 시점에 정해져야 한다.** 같은 실행에서 만드는 방화벽의 엔드포인트 식별자는 적용 전까지 알 수 없다. 식별자가 비어 있는지로 엣지 연결 리소스의 개수를 정하면 처음부터 전체를 만드는 계획이 실패한다. 켜고 끄는 값은 코드에 적힌 값이므로 항상 계획 시점에 알 수 있다.
- **두 단계 적용이 접근 단절에 대한 유일한 안전장치다.** 경로 전환만 담은 두 번째 적용은 7초 만에 끝나며, 문제가 생기면 값을 되돌려 다시 적용하면 된다.
- **모듈 사이의 상호 참조는 순환이 아니다.** Terraform은 모듈 단위가 아니라 리소스 단위로 의존 관계를 판단한다. 서브넷 → 방화벽 → 엔드포인트 → 경로 순서에는 순환이 없고, 계획 단계에서 이를 확인했다. 라우팅을 루트 구성으로 옮길 이유가 없으므로 경로 정의를 한 모듈에 모았다.
- 모듈은 방화벽의 종류를 알지 못한다. 엔드포인트 식별자만 받으므로 Phase 9에서 직접 운영 방식으로 전환할 때 같은 구조에 입력을 추가하면 된다.

## 고려한 대안

**엔드포인트 식별자의 유무로 전환 여부를 판단** — 입력이 하나로 줄어 단순하다. 방화벽과 경로를 같은 실행에서 만들면 식별자를 계획 시점에 알 수 없어 리소스 개수를 정하지 못하고 계획이 실패한다.

**라우팅을 루트 구성에 작성** — 두 모듈의 출력을 모두 볼 수 있다는 이유로 검토했다. 실제로는 모듈 간 상호 참조가 순환을 만들지 않아 필요가 없고, 인터넷 게이트웨이 식별자와 서브넷 대역을 새로 출력해야 하며 경로 정의가 두 곳으로 나뉜다.

**방화벽 생성과 경로 전환을 한 번에 적용** — 적용 횟수가 한 번 줄어든다. 문제가 생겼을 때 원인을 구분할 수 없고 관리 접근이 끊길 위험이 있어 `ADR-015`의 경고와 맞지 않는다.

**경로 리소스를 대상별로 둘로 분리** — 꺼진 상태에서 인터넷 게이트웨이 경로가 방화벽을 기다리지 않게 하려고 검토했다(아래 결과 참조). 전환할 때 같은 목적지의 경로를 삭제하고 생성하는 순서가 보장되지 않아 충돌할 수 있다.

## 결과

- **꺼진 상태에서도 두 기본 경로가 방화벽 생성을 기다린다.** 타깃을 고르는 조건식이 엔드포인트 식별자를 참조하고, Terraform은 조건의 결과와 무관하게 참조를 의존 관계로 본다. 처음부터 전체를 만들면 두 경로가 방화벽 생성(약 6분) 뒤에 만들어진다.
- 그 사이 인스턴스는 나가는 경로 없이 부팅한다. 첫 배포에서 웹 방화벽의 초기 구성이 패키지 저장소 접속 실패로 중단됐다. **부팅 스크립트가 첫 패키지 명령을 제한 시간 안에서 재시도하도록 바꿔 대응했고**, 다음 배포에서 약 5분 뒤 스스로 복구하는 것을 확인했다. 이 대기 시간은 인스턴스 초기 구성 시간(`NFR-07`)에 포함된다.
- **모든 서브넷이 첫 번째 가용영역의 엔드포인트 하나를 쓴다.** 가용영역을 늘리면 교차 가용영역 경로가 된다. NAT이 첫 가용영역에 고정된 것과 같은 한계이며 `NFR-05` 확장 시 함께 고친다.
- 경로를 전환하는 순간 이미 맺어져 있던 세션 관리자 연결 위의 명령 하나가 응답하지 않았다. 새로 보낸 명령은 정상 처리됐다. 전환 직후의 접속 확인은 새 명령으로 한다.
