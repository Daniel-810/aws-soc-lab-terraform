# ADR-019. 웹 방화벽 인바운드를 운영자 주소로 한정하고, 주소는 실행 시점에 조회한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-19 |
| 관련 | `T-44`, `T-43`, `T-11`, `SR-10`, `SR-25`, `AC-05a`, `AC-05b`, `FR-01` |

---

## 맥락

Phase 5는 웹 방화벽 보안그룹의 80과 443 인바운드를 `0.0.0.0/0`으로 열었다. 근거는 경계 계층이 인터넷에서 도달 가능해야 한다는 것이었고, 누구로부터 도달해야 하는지는 정하지 않았다.

그 뒤에 있는 앱은 일부러 취약하게 만든 OWASP Juice Shop이고, `ADR-018`에 따라 룰셋이 없거나 차단하지 않는 단계를 거친다. 공인 주소는 할당되는 순간 자동 스캐너에 노출되므로, 이 기간 동안 공격이 그대로 앱에 도달한다(`T-44`). 또한 외부 스캔 트래픽이 로그에 섞여 `AC-05a`와 `AC-05b`의 측정값을 오염시킨다.

이 랩은 한 사람이 같은 장비에서 배포하고 검증한다. 경계 계층에 도달해야 하는 출발지는 사실상 하나다.

## 결정

**인바운드 80과 443의 출발지를 운영자의 공인 주소(`/32`)로 한정한다.** 네트워크 모듈은 출발지 목록을 변수(`waf_ingress_cidrs`)로 받고 기본값을 두지 않는다. 루트 구성이 `hashicorp/http` 프로바이더로 실행 시점에 운영자 주소를 조회해 전달한다.

## 근거

- **노출 범위가 인터넷 전체에서 주소 하나로 줄어든다.** 스캔 트래픽이 도달하지 않으므로 침해 가능성과 측정 오염이 함께 사라진다.
- **주소를 코드에 적지 않는다.** 공인 주소는 `SR-10`의 대상이다. 실행 시점에 조회하면 저장소에도 별도 파일에도 남지 않는다. 주소가 바뀌어도 다음 계획에서 보안그룹이 따라 갱신되므로 수동 단계가 없다.
- **조회는 루트에서만 한다.** 모듈이 외부 서비스를 호출하면 오프라인에서 쓸 수 없고 테스트에서 값을 주입할 수 없다. 값의 출처는 루트가 정하고 모듈은 받은 값만 쓴다. `ca_secret_arn`, `app_private_ip`와 같은 원칙이다.
- **변수에 기본값을 두지 않는다.** 기본값이 `0.0.0.0/0`이면 호출하는 쪽이 아무것도 하지 않을 때 전면 개방으로 돌아간다. 출발지는 호출하는 쪽이 반드시 정하게 한다.
- 조회 응답은 사후 조건으로 검사한다. 서비스 장애나 프록시가 가로챈 응답이 주소 형식이 아니면 계획 단계에서 멈춘다.

## 고려한 대안

**`-var`로 주소를 직접 입력** — 의존성이 늘지 않는다. 배포할 때마다 주소를 확인해 입력해야 하고, 잊으면 옛 주소가 남거나 계획이 멈춘다. 사람이 기억해야 하는 단계는 재현성(`NFR-03`)을 떨어뜨린다.

**`external` 프로바이더로 로컬 명령 실행** — 같은 결과를 얻지만 운영체제마다 스크립트가 달라지고, 임의 명령을 실행하는 경로가 구성에 들어온다.

**전면 개방 유지 후 룰셋에 의존** — 룰셋이 없는 단계가 설계상 존재하므로 성립하지 않는다.

**세션 관리자 포트 포워딩으로만 접근** — 공인 인바운드를 완전히 닫을 수 있다. 다만 `T-11`이 요구하는 평문과 암호화 경로의 계층별 비교, 그리고 이후 Phase의 네트워크 방화벽 검사가 인터넷에서 들어오는 트래픽을 전제로 하므로 검증 목적과 맞지 않는다.

## 결과

- **프로바이더가 하나 늘어난다.** `hashicorp/http`를 `~> 3.0`으로 고정하고 잠금 파일을 커밋한다(`SR-25`).
- **계획이 외부 서비스에 의존한다.** 조회 서비스가 응답하지 않으면 계획이 실패한다. 사후 조건이 원인을 명확하게 알린다.
- **운영자 주소가 상태 파일과 계획 출력에 남는다.** 상태는 비공개 버킷에 있으므로 수용하고, 계획 출력은 공개 위치에 붙이지 않는다.
- **배포한 장비와 검증하는 장비가 같아야 한다.** 다른 곳에서 검증하려면 변수에 주소를 추가한다.
- **공유 주소 환경에서는 같은 주소의 제3자도 도달할 수 있다.** 전면 개방에 비하면 노출이 극적으로 줄어들지만 0은 아니다.
- 프로덕션에서는 이 방식을 쓰지 않는다. 불특정 사용자를 받는 서비스는 출발지를 제한할 수 없으므로, 룰셋을 차단 모드로 운영하고 속도 제한(`SR-21`)을 적용하는 것이 경계 통제가 된다.
