# ADR-011. 내부 구간 TLS에 코드로 생성한 사설 인증 기관을 사용한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `SR-08`, `F3`, `T-28` |

---

## 맥락

원본은 경계 계층과 내부 워크로드 사이에 자체 서명 인증서를 사용하고 **인증서 검증을 비활성화**했다(`F3`). `SR-08`은 검증을 비활성화하지 않을 것을 요구한다.

## 결정

**Terraform으로 사설 인증 기관을 생성**하고, 서버 인증서를 발급해 내부 구간 TLS에 사용한다. 클라이언트 측에 해당 기관을 신뢰 목록으로 배포해 검증을 활성화한다.

## 근거

- 자체 서명 인증서로는 **검증이 원리적으로 불가능**하다. 검증을 끄면 중간자 공격을 탐지할 수 없어 암호화의 절반이 무의미해진다.
- 관리형 사설 인증 기관 서비스는 월 고정비가 높아 예산(`C-04`)을 초과한다.
- 인증 기관을 코드로 생성하면 비용이 발생하지 않으면서 **검증을 실제로 활성화**할 수 있다.
- 공개 키 기반 구조를 IaC로 다루는 학습 가치가 있다.

## 고려한 대안

**관리형 사설 인증 기관** — 정석이며 수명 주기 관리가 자동화된다. 월 고정비가 예산을 초과한다.

**로드밸런서 + 공인 인증서** — TLS 종단이 로드밸런서로 이동하면서 아키텍처가 바뀌고, 도메인 소유가 필요하다.

## 결과

- 인증 기관의 개인 키가 상태 파일에 포함될 수 있다. `SR-09`(저장 시 암호화)와 `SR-24`(시크릿 비평문 보관)를 반드시 적용한다.
- 인증서 만료 시 재발급이 필요하다. 랩 환경이므로 유효 기간을 길게 설정한다.
- 프로덕션이라면 관리형 인증 기관 또는 공인 인증서를 사용해야 한다.
