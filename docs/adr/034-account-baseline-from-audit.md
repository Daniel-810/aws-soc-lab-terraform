# ADR-034. 자체 감사에서 나온 계정 수준 설정은 상시 환경에 두고, 암호 만료는 두지 않는다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-25 |
| 관련 | `SR-02`, `SR-09`, `SR-05`, `ADR-014`, `ADR-032`, `ADR-033`, `docs/04-audit-prowler.md` |

---

## 맥락

배포된 환경과 계정을 오픈소스 CSPM 도구(Prowler)로 감사했다. 실패 121건 가운데 상당수는 랩의 리소스가 아니라 계정 전체의 기본값이었다(EBS 기본 암호화, IMDSv2 기본값, 계정 수준 퍼블릭 차단, 외부 접근 분석, 암호 정책). 랩의 리소스는 이 설정들을 이미 개별로 지키고 있었다.

## 결정

- **계정 수준 설정 다섯 가지를 상시 환경(`envs/audit`)에 둔다.** EBS 기본 암호화, IMDSv2 필수 기본값, S3 계정 수준 퍼블릭 차단, IAM Access Analyzer, IAM 암호 정책.
- **상태 버킷에 비TLS 요청 거부 정책을 둔다**(`bootstrap`).
- **암호 정책에 주기적 만료를 넣지 않는다.** 길이, 문자 종류, 재사용 금지만 둔다.

## 근거

- **개별 리소스의 설정은 코드 밖에서 만든 리소스를 지키지 못한다.** 계정 기본값은 콘솔이나 다른 도구로 만든 리소스에도 적용된다. 랩의 코드는 이미 명시적으로 설정하므로 결과는 바뀌지 않는다.
- **계정 설정은 랩과 수명이 다르다.** 랩을 지울 때 함께 지워지면 안 된다. 감사 로그와 같은 상시 환경에 둔다(`ADR-032`).
- **비용이 없다.** 다섯 가지 모두 과금되지 않는다(외부 접근 분석기 포함).
- **주기적 암호 만료는 보안을 높이지 않는다.** NIST SP 800-63B는 주기적 변경 강제를 권하지 않는다. 사용자가 예측 가능한 변형을 고르게 만들고, 침해 여부와 무관하게 변경을 요구한다. 변경은 침해 징후가 있을 때 강제한다.

## 고려한 대안

**랩 환경(`envs/lab`)에 두기** — 랩과 함께 관리된다. 랩을 지울 때마다 계정 보호가 사라진다.

**감사 도구의 권고를 전부 따르기(90일 만료 포함)** — 점검 결과가 깨끗해진다. 도구의 기본값이 곧 모범 사례는 아니며, 근거 없이 따르면 결정의 이유를 설명할 수 없다.

**설정하지 않고 수용으로 기록** — 작업이 없다. 비용 없이 닫을 수 있는 지적을 남길 이유가 없다.

## 결과

- 재감사에서 11건이 통과로 바뀌었고 새 실패는 없었다(121건 → 110건).
- 암호 90일 만료 점검은 결정에 따라 실패로 남는다.
- EBS 기본 암호화, IMDSv2 기본값, 외부 접근 분석기는 리전 단위 설정이다. 이 계정은 서울 리전만 쓰므로 한 곳에만 둔다. 다른 리전을 쓰게 되면 그 리전에도 필요하다.
- 암호 정책은 기존 암호를 무효로 하지 않는다. 다음 변경부터 적용된다.
