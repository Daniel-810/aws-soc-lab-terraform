# ADR-030. CloudWatch는 수집 지점과 조사 도구로 쓰고, 수집 대상은 선별한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-25 |
| 관련 | `FR-05`, `FR-06`, `SR-14`, `SR-15`, `SR-16`, `NFR-04`, `NFR-06`, `F7`, `F10`, `F12`, `F13`, `T-06`, `T-13` |

---

## 맥락

`FR-05`는 각 계층의 로그를 단일 지점으로 모으고, `FR-06`은 공격자 주소와 탐지 룰과 페이로드를 조회하고 시각화하라고 요구한다. 방화벽 경보(방식 A)는 Phase 8부터 CloudWatch에 있고, 웹 방화벽과 Suricata의 로그는 인스턴스 디스크에 있다.

실무 보안관제의 중심은 SIEM이다. CloudWatch, CloudTrail, VPC 흐름 로그는 대개 SIEM에 넣는 원천이다.

## 결정

- **CloudWatch를 수집 지점과 조사 도구로 쓴다.** 저장 쿼리와 대시보드를 둔다. SIEM은 두지 않는다.
- **수집 대상을 선별한다.** 웹 방화벽은 감사 로그만(이미 규칙에 걸린 트랜잭션만 기록), Suricata는 경보만 보낸다. 앱 인스턴스는 보안 계층이 아니므로 에이전트를 두지 않는다.
- **VPC 흐름 로그는 허용과 거부를 모두 기록한다.**
- **로그 스트림 이름은 인스턴스 식별자가 아닌 고정 이름을 쓴다.**
- **두 방식의 경보를 한 쿼리로 읽는다.** 관리형은 레코드를 한 겹 감싸고 Suricata는 감싸지 않으므로, 두 경로 중 있는 쪽을 읽도록 쿼리를 쓴다.
- 모든 로그 그룹의 보존 기간은 14일이다.

## 근거

- **수집 단계의 작업은 SIEM을 붙여도 그대로 필요하다.** 에이전트 설치, 선별, 마스킹, 형식 통합은 SIEM 앞단이다. 이 환경이 만드는 것은 그 앞 절반이다.
- **SIEM을 추가하는 선택지는 비용이나 범위를 넘는다.** 관리형 검색 서비스는 가장 작은 노드도 상시 과금이라 `NFR-04`를 잠식한다. 직접 운영형은 메모리 요구가 커서 인스턴스 비용이 늘고, 프로젝트 초기에 제외한 도구를 다시 들이게 된다. 정규화 저장소(OCSF)는 자체 로그의 변환 파이프라인을 새로 만들어야 한다.
- **선별은 원본 결함의 해소다.** 원본은 무조건 기록 규칙으로 정상 요청까지 전량 수집했다(`F12`). 수집량은 곧 비용이고, 정상 형태의 요청 대량 전송만으로 비용을 올리는 경로(`T-13`)의 증폭 계수가 된다. Suricata의 흐름과 통계 이벤트는 VPC 흐름 로그와 겹치거나 양만 많다.
- **흐름 로그는 규칙이 보지 못한 것을 남긴다.** 경보 로그는 규칙에 걸린 것만 기록하므로, 통과한 트래픽과 미탐은 흐름 로그로만 확인할 수 있다(`F10`, `T-06`).
- **고정된 경로는 인스턴스 교체에도 끊기지 않는다.** 원본은 수집 설정이 인터페이스 이름에 묶여 재생성 시 파이프라인이 조용히 끊겼다(`F13`).
- **방식을 바꿔도 대시보드가 그대로 동작한다.** 두 방식은 같은 엔진 계열이라 필드 이름이 같고 감싼 층만 다르다.

## 고려한 대안

**관리형 검색 서비스(OpenSearch)로 SIEM 구성** — 상관 분석과 경보 운영까지 가능하다. 상시 과금으로 월 예산을 크게 잠식한다.

**직접 운영형 SIEM을 인스턴스에 설치** — 비용은 인스턴스 요금뿐이나 메모리 요구가 크고, 운영 범위가 Phase 하나 분량으로 늘어난다.

**정규화 저장소(OCSF)** — AWS 원천 로그는 자동으로 변환된다. 웹 방화벽과 Suricata 로그의 변환을 직접 만들어야 한다.

**방식별로 쿼리 분리** — 쿼리가 단순하다. 방식을 바꿀 때마다 대시보드도 바꿔야 한다.

## 결과

- 상관 분석 규칙과 자동 경보는 이 환경에 없다. 조사는 사람이 쿼리로 한다. 프로덕션 구성과의 차이로 아키텍처 문서 5.1절에 기록했다.
- 웹 방화벽 로그는 구조가 달라 별도 쿼리로 둔다.
- 흐름 로그는 VPC 전체를 기록하므로 수집량이 가장 많은 원천이 된다. 이 환경은 검증 시점에만 기동하므로 감당 가능하며, 상시 기동이면 필드와 대상 인터페이스를 줄인다.
- 보안 로그(CloudWatch)의 삭제 방지(`SR-17`)는 이 문서의 범위가 아니다. 감사 로그와 함께 별도로 다룬다.
