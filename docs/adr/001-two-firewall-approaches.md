# ADR-001. 두 방화벽 방식을 비교 구성한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `FR-04`, `C-03` |

---

## 맥락

원본 환경은 방화벽 계층을 관리형과 오픈소스 두 방식으로 각각 구축해 비교했다. 재구성에서도 이 구조를 유지할지, 관리형 하나로 단순화할지 결정해야 한다.

## 결정

동일한 요구사항을 **관리형 방화벽**과 **직접 운영 방식** 두 가지로 각각 구성하고, 라우팅 타깃 변경으로 전환 가능하게 한다.

## 근거

- `FR-04`가 이 프로젝트의 존재 이유다. 두 방식을 모두 구현해야 트레이드오프를 **측정**할 수 있다.
- 두 방식 모두 동일한 Suricata 엔진을 사용하므로 **엔진 차이가 아닌 운영 모델 차이만** 비교된다.
- 직접 구축해야 관리형이 무엇을 대신해주는지 구체적으로 말할 수 있다. 실제로 설계 과정에서 직접 운영 방식에만 필요한 항목이 다섯 가지 확인됐다 — 패킷 포워딩 활성화, 소스/대상 확인 해제, 큐 실패 모드 결정, 보안그룹을 좁힐 수 없음, 패치·룰셋 배포 직접 관리.

## 고려한 대안

**관리형만 구성한다** — 구축 기간이 크게 줄고 프로덕션 표준에 가깝다. 그러나 비교 대상이 사라져 `FR-04`가 성립하지 않으며, 제출된 지원 서류의 "방화벽 2가지 방식 비교" 서사와 어긋난다.

## 결과

- 구축 기간이 늘어난다. 직접 운영 방식에만 필요한 설정 항목이 다섯 가지 추가된다.
- 이 환경은 **프로덕션 아키텍처가 아니라 검증 환경**이 된다. 문서와 발표에서 "이렇게 구축하는 것을 권장한다"가 아니라 **"두 방식을 검증한 결과 이 조건에서는 이쪽을 권한다"**로 서술해야 한다.
- 비교 결론이 "관리형 권장"으로 나와도 무방하다. 직접 해보고 내린 결론이라는 점이 근거가 된다.
