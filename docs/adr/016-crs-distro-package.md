# ADR-016. OWASP CRS를 배포판 패키지 3.3.5로 적용한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-08 |
| 관련 | `SR-11`, `SR-22`, `SR-25`, `NFR-07`, `ADR-002`, `ADR-006`, `F1` |

---

## 맥락

원본 환경의 웹 방화벽에는 룰셋이 설치되지 않아 탐지 룰이 0개였다(`F1`). `ADR-002`가 그 해소 방법으로 OWASP CRS 적용을 정했고, `SR-11`이 이를 필수 요구사항으로 고정했다. 남은 것은 **어느 버전을 어떤 경로로 설치하는가**이다.

2026-09-05에 Ubuntu 24.04 저장소를 확인한 결과 필요한 패키지가 모두 존재했다.

| 패키지 | 버전 | 섹션 |
|---|---|---|
| `libnginx-mod-http-modsecurity` | 1.0.3-1build3 | universe |
| `libmodsecurity3t64` | 3.0.12-1.1build2 | universe |
| `modsecurity-crs` | 3.3.5-2 | universe |

CRS의 상위 버전인 v4는 저장소에 없다. 사용하려면 배포처의 릴리스 아카이브를 직접 내려받아 배치해야 한다.

## 결정

**배포판 패키지의 CRS 3.3.5를 채택한다.** v4를 직접 내려받지 않으며, 설치는 패키지 관리자로만 수행한다. 버전은 초기화 스크립트에 명시해 고정한다.

## 근거

- **무결성 검증 경로가 이미 있다.** 저장소 패키지는 배포판 서명으로 검증되므로 `SR-25`가 요구하는 공급망 통제가 도구 차원에서 성립한다. 릴리스 아카이브를 직접 내려받으면 그 검증을 직접 만들어야 하고, 검증 코드를 스스로 작성한 시점부터 그것이 새로운 신뢰 지점이 된다.
- **보안 업데이트가 자동으로 이어진다.** `SR-22`는 보안 소프트웨어가 업데이트를 지속적으로 수신할 수 있는 방식으로 설치될 것을 요구한다. 패키지 관리자로 설치하면 이 조건이 설치 방식 자체로 충족되지만, 직접 내려받은 룰셋은 갱신이 사람의 기억에 의존한다.
- **`NFR-07`의 5분 예산을 지키기 유리하다.** 다운로드와 압축 해제, 배치 단계가 사라진다. 이번 Phase는 웹 방화벽과 인증 기관 구성이 한꺼번에 들어가 초기 구성 예산의 대부분을 쓴다.
- **이 랩의 목적은 최신 룰셋 사용이 아니다.** 해소하려는 결함은 "룰셋이 0개였던 것"이지 "룰셋이 구버전이었던 것"이 아니다. 3.3.5도 공개적으로 관리되는 룰셋이므로 `SR-11`을 충족한다.

## 고려한 대안

**릴리스 아카이브의 CRS v4** — 오탐이 상당히 개선되었고 파라노이아 레벨 구성도 정리되었다. 기술적으로는 이쪽이 낫다. 채택하지 않은 이유는 무결성 검증과 갱신 경로를 직접 구성해야 하기 때문이며, 그 부담이 `SR-25`와 `SR-22` 두 항목에 동시에 걸린다. 검증 로직을 작성하면 채택할 수 있으나, 그 작업은 이 Phase가 해소하려는 결함과 관련이 없다.

**관리형 웹 방화벽의 관리 룰 그룹** — 룰셋 관리 자체가 사라진다. `ADR-002`에서 비용과 학습 목표를 근거로 이미 배제했다.

**룰셋 없이 직접 작성한 룰만 사용** — 원본 환경이 사실상 이 상태였고, 그것이 `F1`이다. 검토 대상이 아니다.

## 결과

- **universe 저장소에 의존한다.** 세 패키지 모두 main이 아니라 커뮤니티가 관리하는 영역에 있어 배포사의 보안 업데이트 보장이 main보다 약하다. 업데이트를 받을 수 없는 것은 아니므로 `SR-22` 위반은 아니지만, 보장 수준이 다르다는 점은 기록해 둔다. 프로덕션이라면 이 차이가 도입 검토 항목이 된다.
- **오탐이 v4보다 많을 것으로 예상된다.** 그만큼 `SR-12`가 요구하는 튜닝 근거 기록의 비중이 커진다. 조정 항목과 이유를 남기는 절차는 `ADR-018`에서 정한다.
- **버전을 코드에 명시한다.** 패키지 이름만 적으면 저장소가 갱신될 때 룰셋이 조용히 바뀌어 탐지율 측정의 재현성이 깨진다(`NFR-03`). 이미지 고정과 같은 이유다.
- 프로덕션에서 이 룰셋을 도입한다면 v4를 사용하고, 배포처 서명 검증을 포함한 갱신 파이프라인을 별도로 구성한다.
