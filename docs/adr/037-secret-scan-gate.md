# ADR-037. 병합 전에 커밋 이력 전체를 비밀값 검사하고, 계정 ID는 형태로 막는다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-04 (결정), 2026-10-05 (기록) |
| 관련 | `SR-10`, `SR-25`, `NFR-08`, `AC-09`, `F16`, `ADR-007`, `ADR-033` |

> 결정은 CI를 처음 만든 2026-09-04에 했고, 그때는 ADR로 남기지 않았다. 이 문서는 커밋(`ad5944d`, `2c7a321`)과 작업 기록을 바탕으로 나중에 적은 것이다.

---

## 맥락

저장소는 2026-09-04에 공개로 바뀌었다. 공개 저장소에 한 번 올라간 커밋은 지워도 포크와 캐시에 남으므로, 병합된 뒤에 발견하면 이미 늦다. `SR-10`은 저장소에 자격 증명, 계정 식별자, 공인 IP가 없을 것을 요구한다.

원본 환경에는 계정 ID가 문서와 설정에 그대로 적혀 있었다(`F16`). 비밀값 검사 도구의 기본 규칙은 액세스 키, 개인 키, 토큰은 잡지만 계정 ID는 잡지 않는다. 계정 ID는 비밀번호가 아니라서 기본 규칙의 대상이 아니다.

## 결정

- **비밀값 검사(gitleaks)를 CI의 필수 게이트로 둔다.** 실패하면 병합할 수 없다.
- **커밋 이력 전체를 검사한다**(`fetch-depth: 0`). 최신 커밋만 보지 않는다.
- **기본 규칙에 프로젝트 규칙 두 개를 더한다**(`.gitleaks.toml`, `useDefault = true`).
  - ARN 안의 12자리 계정 ID(`aws-account-id-in-arn`)
  - 계정 ID가 들어간 상태 버킷 이름(`state-bucket-with-account-id`)
- **규칙은 값이 아니라 형태로 쓴다.** 실제 계정 ID를 적어 두고 그것을 찾게 하지 않는다.
- **예외는 0으로 채운 견본(`000000000000`)만 허용한다.** 견본 파일(`backend.hcl.example`)과 모듈 테스트의 모의 ARN이 이 형식을 쓴다.
- 검사는 gitleaks 공식 액션으로 돌리고, 액션은 커밋 해시로 고정한다(`SR-25`).

## 근거

- **병합 전에 막아야 한다.** 공개 저장소에서는 병합 후의 발견이 곧 노출이다. 사람의 리뷰는 놓칠 수 있으므로 자동 게이트로 둔다.
- **지운 비밀값도 이력에 남는다.** 앞 커밋에서 넣고 뒤 커밋에서 지우면, 최신 코드만 보는 검사는 통과하지만 이력에서는 그대로 읽힌다.
- **계정 ID는 비밀은 아니지만 공격자의 일을 줄인다.** 역할 ARN을 짐작할 수 있게 하고, 계정을 열거나 혼동된 대리인 시도의 구체적인 대상으로 만든다(`ADR-036`).
- **값으로 쓰면 그 파일이 유출이 된다.** 실제 계정 ID를 규칙이나 예외 목록에 적으면, 검사 설정 파일 자체가 공개 저장소에 계정 ID를 올리게 된다. 형태로 쓰면 어떤 계정이든 잡힌다.
- **예외를 좁게 둔다.** 0으로 채운 값만 허용하면 견본과 테스트는 통과하고, 다른 12자리 숫자는 계속 잡힌다.

## 고려한 대안

**사람의 리뷰로만 확인** — 도구 없이 된다. 혼자 하는 저장소라 리뷰하는 사람이 작성자 자신이고, 놓쳤을 때 되돌릴 수 없다.

**최신 커밋만 검사** — 빠르다. 지운 비밀값을 놓친다.

**실제 계정 ID를 예외나 규칙에 값으로 적기** — 정확하다. 설정 파일이 곧 유출이 된다.

**gitleaks 바이너리를 직접 받아 해시로 고정** — Trivy와 같은 방식으로, 신뢰할 대상이 배포 파일 하나다(`ADR-033`). 공식 액션 v3가 개인 계정의 공개 저장소에서 라이선스 키 없이 동작하는 것을 첫 CI 실행에서 확인해, 커밋 해시로 고정한 액션을 유지했다.

## 결과

- 처음 만들 때 양성과 음성을 로컬에서 시험했다. 실제 형태의 ARN과 버킷 이름은 잡히고, 0으로 채운 견본, CIDR, AMI 이름, 인스턴스 ID는 통과했다.
- 공개로 바꾸기 전에 이력 전체에 계정 ID가 없는 것을 확인했다(2026-09-04).
- **2026-09-25, 모듈 테스트를 추가한 첫 CI에서 이 검사가 실패했다.** 테스트의 모의 ARN(0으로 채운 계정)이 ARN 규칙에 걸렸다. 예외를 「ARN 안의 0으로 채운 계정」으로만 좁게 추가했고(`2c7a321`), 다른 12자리는 계속 잡히는 것을 확인했다. 게이트가 새 코드를 막은 사례다(`ADR-033` 결과).
- **로컬 커밋 단계의 검사(pre-commit 훅)는 두지 않았다.** CI가 실제 게이트라 병합은 막히지만, 브랜치에 푸시한 커밋은 공개 저장소에 올라간 뒤에 검사된다. 필요하면 `gitleaks protect --staged`로 커밋 전에 막을 수 있다.
- 이 검사는 저장소의 텍스트만 본다. 이미지나 바이너리 안의 값, 그리고 저장소 밖(로컬 측정 결과, `backend.hcl`)은 `.gitignore`로 관리한다.
