# ADR-014. 상태 버킷 암호화에 서비스 관리 키(AES256)를 사용한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `SR-09`, `T-22`, `NFR-04` |

---

## 맥락

Terraform 상태 파일에는 리소스 속성이 **평문으로** 기록된다(`T-22`).
상태 버킷은 저장 시 암호화해야 하며(`SR-09`), 객체 저장소는 두 가지 암호화 방식을 제공한다.

- **서비스 관리 키(AES256)** — 저장소 서비스가 키를 직접 관리한다. 추가 비용이 없다.
- **키 관리 서비스(KMS) 키** — 별도 키를 만들어 사용한다. 키당 월 약 $1과 요청당 과금이 발생한다.

## 결정

**서비스 관리 키(AES256)를 사용한다.** 별도 키 관리 서비스 키를 만들지 않는다.

## 근거

- `SR-09`(저장 시 암호화)는 서비스 관리 키로 충족된다. 저장된 객체는 암호화된다.
- 월 예산이 50,000원이고(`NFR-04`) 검사 계층 기동에 대부분이 소요된다.
  상시 과금 항목을 늘리면 **실제 검증에 쓸 시간이 줄어든다.**
- 운영자가 1인이므로(`C-03`) 아래 "고려한 대안"의 이점 대부분이 실현되지 않는다.

## 고려한 대안

**키 관리 서비스 키(SSE-KMS)** — 두 가지 이점이 있다.

1. **접근 통제가 이중화된다.** 버킷 정책과 별개로 **키 정책**이 존재하므로,
   버킷에 접근 가능한 주체라도 키 정책에서 거부되면 복호화하지 못한다.
   상태 파일을 읽을 수 있는 주체를 관리자 권한과 분리할 수 있다.
2. **복호화 이력이 감사 로그에 남는다.** 누가 언제 상태를 읽었는지 사후 추적이 가능하다(`SR-23` 보강).

**다중 사용자 환경이라면 이쪽이 맞다.** 채택하지 않은 이유는 보안 수준이 아니라
**1인 환경에서 두 이점이 실현되지 않는 것**과 **예산**이다.
운영자가 한 명이면 "관리자와 상태 열람자를 분리한다"는 통제가 성립하지 않고,
복호화 주체도 항상 동일하다.

## 결과

- **상태 파일 접근 통제가 버킷 정책과 IAM 한 겹에만 의존한다.**
  버킷에 접근 가능한 주체는 상태를 그대로 읽을 수 있다.
- **복호화 이력이 남지 않는다.** 상태 파일 열람 여부는 객체 접근 기록으로만 간접 확인한다.
- 이 결정은 `T-22`(상태 파일 평문 노출)를 **완전히 해소하지 않는다.**
  저장 시 암호화는 저장 매체 유출에 대응하며, **접근 권한을 획득한 주체에는 대응하지 못한다.**
  해당 경로는 `SR-06`(최소 권한)과 퍼블릭 접근 차단으로 대응한다.
- **다중 사용자 또는 다계정으로 확장하는 시점에 재검토 대상이다.**
  그 시점에는 접근 통제 이중화의 이점이 실제로 발생한다.
