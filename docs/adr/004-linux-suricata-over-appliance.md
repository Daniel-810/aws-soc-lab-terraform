# ADR-004. 직접 운영 방화벽을 리눅스 + Suricata로 구성한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `FR-02`, `SR-14`, `F13` |

---

## 맥락

원본은 직접 운영 방식으로 BSD 계열 방화벽 어플라이언스를 사용했다. 재구성에서 유지할지 결정한다.

## 결정

**Ubuntu + Suricata inline IPS**로 교체한다.

## 근거

세 가지 문제가 확인됐다.

1. **유료 구독** — 마켓플레이스 사용량 기반 과금. `C-04`(비용 제약)와 충돌한다.
2. **로그 수집 경로가 취약** — BSD 계열이라 공식 로그 에이전트가 없어 별도 수집 도구로 우회해야 했고, 그 설정이 **네트워크 인터페이스 이름에 종속**되어 인스턴스를 재생성하면 파이프라인이 조용히 끊겼다.
3. **설정을 코드화할 수 없음** — 설정이 GUI로 편집하는 XML 덩어리라 IaC 범위 밖에 남는다.

리눅스로 교체하면 세 가지가 모두 해소된다. WAF 인스턴스와 **동일한 로그 에이전트**를 쓰고, 로그 경로가 고정되며, 설정이 전부 텍스트 파일이라 코드로 관리된다.

**부수 효과** — 관리형 방화벽도 Suricata 엔진을 사용하므로 **양쪽 엔진이 같아져 비교가 공정해진다.**

## 고려한 대안

**동일 계열 오픈소스 어플라이언스로 교체** — 무료이고 REST API가 있어 설정 코드화가 가능하다. 그러나 **동일하게 BSD 계열이라 로그 수집 문제가 해소되지 않는다.**

**Debian 기반 네트워크 OS** — 설정이 텍스트 기반이라 IaC 친화적이다. 그러나 IPS 기능이 약해 이 프로젝트의 비교축이 성립하지 않는다.

## 결과

- 제출된 서류에는 원본 제품명이 기재되어 있다. **모순이 아니라 개선**으로 설명한다 — 서류는 2025년 시점의 사실이고, 재구성은 그 한계를 발견해 고친 결과다.
- 어플라이언스 GUI 운영 경험은 얻지 못한다.
- `F13`(경유 인스턴스에 포워딩 미설정)은 이번 구성에서 명시적으로 해소한다.
