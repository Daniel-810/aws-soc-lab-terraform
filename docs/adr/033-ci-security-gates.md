# ADR-033. CI에 IaC 보안 검사와 모듈 테스트를 게이트로 둔다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-25 |
| 관련 | `NFR-08`, `SR-25`, `AC-08`, `ADR-014`, `ADR-017`, `ADR-019`, `ADR-024`, `ADR-027`, `ADR-028`, `ADR-032` |

---

## 맥락

CI는 비밀값 검사, 형식 검사, 구문 검증만 했다. 구문이 맞으면 보안 설정이 빠져도 통과한다. 실제로 Phase 11에서 처음 IaC 보안 검사를 돌리자, 세 인스턴스의 루트 볼륨이 암호화되지 않은 채로 지금까지 배포돼 왔다는 것이 드러났다.

## 결정

- **IaC 보안 검사(Trivy)를 CI 게이트로 둔다.** HIGH와 CRITICAL이 있으면 병합할 수 없다. 기본값(방식 A)과 방식 B를 선택한 상태로 두 번 검사한다.
- **설계상 수용한 지적은 해당 리소스 바로 위에 이유와 함께 예외 표시(`#trivy:ignore`)를 단다.** 별도 예외 파일에 모으지 않는다.
- **모듈 테스트(`terraform test`)를 모의 AWS 제공자로 돌린다.** 자격증명 없이 경로 전환, 경계 개방 범위, IMDSv2, 볼륨 암호화, 검사 인스턴스의 전달 설정을 고정한다.
- 검사 도구는 서드파티 액션이 아니라 바이너리를 직접 받아, 버전과 배포 파일의 SHA-256으로 고정한다.

## 근거

- **구문 검증은 의미를 보지 않는다.** 루트 볼륨 암호화 누락은 `fmt`, `validate`, `plan`, 실제 배포까지 모두 통과했다.
- **예외는 리소스 곁에 둔다.** 파일 단위로 예외를 두면 같은 파일에 새로 추가한 같은 종류의 리소스도 조용히 통과한다. 리소스 단위 예외는 새 리소스를 다시 검사하게 만들고, 이유가 코드와 함께 읽힌다.
- **방식 B를 따로 검사한다.** 기본값에서는 방식 B 모듈의 개수가 0이라 검사 대상에서 빠진다.
- **테스트는 결정을 고정한다.** 보안 검사 도구는 일반 규칙을 보고, 이 프로젝트의 결정(웹 방화벽은 운영자 주소만, 검사를 켜면 들어오는 경로도 같은 엔드포인트, 방식 B는 전달 설정 필수)은 모른다. 테스트가 그 결정을 지킨다.
- **CI는 계정에 접근하지 않는다.** 모의 제공자는 자격증명이 필요 없다. 기존 원칙(역할을 수임하지 않는 CI)을 유지한다.
- **도구를 직접 받는 것은 공급망을 줄인다.** 서드파티 액션은 내부에서 설치 스크립트를 내려받아 실행한다. 버전과 해시를 고정한 바이너리는 신뢰할 대상이 배포 파일 하나다(`SR-25`).

## 고려한 대안

**예외 파일(`.trivyignore`)에 모으기** — 한곳에서 보인다. 파일 단위 경로 예외는 같은 파일의 새 리소스를 숨긴다.

**모든 심각도에서 실패** — 가장 엄격하다. 비용과 관리 부담 때문에 수용한 LOW 지적(고객 관리형 키 등)이 설계 결정의 결과라, 게이트를 HIGH 이상에 두고 LOW는 예외 표시와 이유로 관리한다.

**실제 계정에 배포하는 통합 테스트** — 가장 사실에 가깝다. CI에 자격증명과 비용이 필요하고, 공개 저장소의 CI가 계정에 접근하게 된다.

**Checkov 등 다른 검사 도구** — 규칙 범위는 비슷하다. 하나를 게이트로 운영하는 것이 판단을 단순하게 한다.

## 결과

- **고친 것**: 세 인스턴스의 루트 볼륨 암호화(`AWS-0131`). 인스턴스가 교체되는 변경이며 다음 배포에서 반영된다.
- **수용한 것**(리소스 곁에 이유 표시): 아웃바운드 전체 허용 4건(`AWS-0104`, 패키지 저장소와 세션 관리자의 주소가 고정되지 않음, 검사 인스턴스는 전달 목적지를 알 수 없음), 고객 관리형 키 7건(`ADR-014`, `ADR-032`), 버킷 접근 로그 2건, CloudTrail의 CloudWatch 사본 1건, 시크릿 고객 관리형 키 1건(공개 인증서만 보관, `ADR-017`).
- 모듈 테스트 16개. 코드를 일부러 되돌려(IMDSv2 선택으로, 전달 설정 켬으로, 흐름 로그를 거부만으로, 검사를 켜도 게이트웨이로) 네 경우 모두 테스트가 실패하는 것을 확인했다. 볼륨 암호화를 끄자 보안 검사 게이트도 실패했다.
- **모의 제공자는 코드가 설정한 값만 검사할 수 있다.** 설정하지 않은 값(키 페어 이름, 공인 주소 할당 여부)은 모의 제공자가 임의 값으로 채운다. 그래서 「SSH 키 없음」은 테스트가 아니라 보안 그룹과 부팅 스크립트가 보장하고, 「앱은 사설」은 앱 서브넷의 경로(NAT만)로 검사한다.
- 모의 제공자는 정책 문서와 ARN도 임의 문자열로 채워, 유효한 형식의 값을 지정해 줘야 했다.
