# ADR-035. 콘솔에서 만든 예산 알람을 코드로 가져와 관리한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-26 |
| 관련 | `NFR-01`, `NFR-04`, `SR-10`, `AC-01`, `ADR-032` |

---

## 맥락

월 예산 알람은 Phase 4에서 리소스를 만들기 전에 콘솔로 만들었다. 첫 실수부터 잡으려면 코드보다 먼저 있어야 했다. 그 결과 Phase 11 판정에서 이것이 코드로 정의되지 않은 유일한 구성 요소로 남아 `NFR-01`과 `AC-01`이 부분 충족이 됐다.

## 결정

- **예산을 상시 환경(`envs/audit`)의 코드로 정의하고, 기존 예산을 CLI로 가져와(`terraform import`) 연결한다.** 가져오기 블록은 코드에 남기지 않는다.
- **알림 수신 주소는 변수로 받고, git에서 제외되는 로컬 파일(`terraform.tfvars`)에서 넣는다.** 형식은 예시 파일로 남긴다.
- **콘솔이 넣어 둔 설정을 그대로 코드에 옮긴다.** 특히 크레딧과 환불을 뺀 비용으로 측정하는 필터를 유지한다.

## 근거

- **가져오면 알림이 끊기지 않는다.** 새로 만들고 옛것을 지우면 그 사이에 알림 공백이 생기고, 이미 쌓인 월간 집계도 새로 시작한다.
- **가져오기 블록을 남기지 않아야 빈 계정에서도 코드만으로 만들어진다.** 블록이 있으면 가져올 대상이 없는 계정에서 적용이 실패한다.
- **수신 주소는 개인정보다.** 공개 저장소에 넣지 않는다(`SR-10`). 변수 검증으로 비어 있는 목록은 거부한다.
- **크레딧을 빼지 않으면 예산이 무력해진다.** 이 계정은 크레딧으로 요금을 낸다. 크레딧 차감 후 비용은 0으로 보여, 실제 사용량이 늘어도 크레딧이 떨어질 때까지 알림이 오지 않는다. 처음 작성한 코드에는 이 필터가 없었고, 가져온 뒤 계획에서 필터를 지우려는 변경으로 드러났다.

## 고려한 대안

**예산을 새로 만들고 콘솔 예산은 삭제** — 가져오기 절차가 필요 없다. 알림 공백과 집계 초기화가 생긴다.

**가져오기 블록을 코드에 남기기** — 가져온 사실이 코드에 기록된다. 빈 계정에서 적용이 실패한다.

**수신 주소를 코드에 적기** — 설정이 한곳에 있다. 공개 저장소에 개인정보가 들어간다.

## 결과

- 가져온 뒤 계획은 「변경 없음」이었다. 코드와 실제 예산이 일치한다.
- 예산 이름은 콘솔이 붙인 기본 이름(`My Monthly Cost Budget`)을 유지했다. 이름을 바꾸면 예산이 교체된다.
- 새로 배포하는 사람은 예시 파일을 복사해 수신 주소를 채워야 한다. 비어 있으면 계획 단계에서 거부된다.
