# ADR-007. 장기 액세스 키를 생성하지 않고 콘솔 로그인으로 임시 자격 증명을 받는다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-02 |
| 관련 | `SR-05`, `SR-06`, `SR-23`, `T-31`, `T-34`, `T-35` |

---

## 맥락

원본 매뉴얼은 IAM 사용자 생성으로 끝난다. 장기 액세스 키를 사용하는 방식이며,
액세스 키는 만료되지 않으므로 **유출 시 무기한 유효**하다. 유출 시점을 인지하기도 어렵다.
`T-31`(운영자 자격 증명 탈취)의 피해가 시간적으로 제한되지 않는다.

초안에서는 이를 **통합 인증 서비스(IAM Identity Center)**로 해결하려 했으나 제약이 확인됐다.
통합 인증 서비스는 **조직(Organizations) 활성화를 전제**로 하고, 이 계정에서 조직을 활성화하면
**무료 요금제와 잔여 크레딧이 소멸**한다. 월 예산이 50,000원(`NFR-04`)이고 크레딧이 실질 재원이므로
도입 비용이 예산 전체를 초과한다.

## 결정

**장기 액세스 키를 생성하지 않는다.** 조직 활성화도 하지 않는다.

- **콘솔 로그인 자격 증명으로 명령줄 임시 자격 증명을 발급**받는다(AWS CLI `login`, 2.32 이상).
  액세스 키 파일(`credentials`)을 아예 만들지 않는다.
- 로그인한 IAM 사용자에게는 **작업 권한을 부여하지 않는다.** 권한은 별도 **역할**에 두고,
  그 역할을 수임해 받은 자격 증명으로만 작업한다.
- 역할 신뢰 정책에 **다중 인증 조건**(`aws:MultiFactorAuthPresent`)을 걸어 MFA 없이는 수임을 거부한다.
- 역할 세션은 **1시간**, 콘솔 로그인 세션은 최대 12시간 후 만료되며 재로그인이 필요하다.

## 근거

- **만료되지 않는 자격 증명이 환경에 하나도 존재하지 않는다.** `SR-05`를 타협 없이 충족한다.
- 사용자 자체에 작업 권한이 없으므로, 로그인 세션이 탈취되어도 **역할을 수임하지 못하면 아무것도 할 수 없다.**
  수임에는 다중 인증이 필요하다.
- 조직을 활성화하지 않으므로 크레딧이 유지된다. 예산 제약과 충돌하지 않는다.
- 추가 비용이 없다.

## 고려한 대안

**통합 인증 서비스(IAM Identity Center)** — 다계정 환경의 표준이며 권한 집합 관리가 체계적이다.
그러나 조직 활성화가 전제이고, 이 계정에서는 크레딧 소멸을 수반한다.
**보안 수준은 채택안과 실질적으로 동등한 반면 재원 손실이 커서 채택하지 않는다.**
다계정으로 확장하는 시점에는 이쪽이 맞다.

**IAM 사용자 + 장기 액세스 키 + 다중 인증** — 설정이 가장 간단하고 모든 도구가 지원한다.
그러나 만료되지 않는 자격 증명이 남아 원본의 문제를 반복한다.
키에 역할 수임 권한만 주어 피해를 제한하는 절충안도 검토했으나,
**콘솔 로그인 방식으로 키 자체를 없앨 수 있어 채택하지 않는다.**

## 결과

- **로그인에 별도 권한이 필요하다.** 명령줄 로그인은 `signin:AuthorizeOAuth2Access`·`signin:CreateOAuth2Token`
  두 액션을 요구하며, 관리형 정책 `SignInLocalDevelopmentAccess`로 부여한다.
  이 정책은 리소스 접근 권한을 포함하지 않으므로 "사용자 권한 0" 원칙이 유지된다.
  - **최소 권한을 끝까지 적용하면 인증 경로 자체가 막힌다는 실례다.**
    권한을 넓혀 해결하지 않고, 필요한 액션만 담긴 정책을 찾아 부여하는 것으로 해소했다.
- **인프라 도구(SDK)는 이 세션을 직접 읽지 못한다.** Terraform은 명령줄 로그인 세션을 인식하지 못하므로,
  자격 증명을 외부 프로세스로 노출하는 설정(`credential_process`)을 경유해 연결한다.
  검증 결과 역할 수임까지 정상 동작한다.
- 최대 12시간마다 재로그인이 필요하다. 역할 세션은 1시간이며 자동 갱신된다.
- 설정 파일에 **주석을 넣을 수 없다.** 설정 파서가 주석 줄에서 실패한다.
- 이 결정은 **단일 계정·운영자 1인** 조건에 맞춘 것이다(`C-01`, `C-03`). 다계정으로 가면 재검토 대상이다.
