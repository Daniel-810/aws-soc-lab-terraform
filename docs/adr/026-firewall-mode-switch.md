# ADR-026. 검사 방식은 변수 하나로 선택하고, 한 번에 한 방식만 배포한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 |
| 일자 | 2026-09-25 |
| 관련 | `FR-04`, `NFR-04`, `ADR-001`, `ADR-022`, `ADR-024` |

---

## 맥락

Phase 9에서 직접 운영 방식(Suricata 인스턴스)이 추가되면서 검사 계층이 두 가지가 됐다. 두 방식은 같은 서브넷 구조와 같은 라우팅 구조를 쓰고, 경로의 타깃만 다르다. 관리형은 방화벽 엔드포인트를, 직접 운영은 인스턴스의 네트워크 인터페이스를 타깃으로 쓰며, 경로 리소스에서 두 타깃은 서로 다른 인자로 지정된다.

아키텍처 문서는 방식 선택 변수를 예고했으나 형태를 정하지 않았다. `ADR-024`는 경로 전환을 별도 값으로 두었다.

## 결정

**루트 구성의 `firewall_mode`(`managed` 또는 `oss`)로 배포할 방식을 고르고, 선택된 방식의 모듈만 생성한다.** 경로 전환(`route_through_firewall`)은 이와 별개로 유지한다.

- 네트워크 모듈은 엔드포인트 식별자와 네트워크 인터페이스 식별자를 따로 받고, 경로를 켰을 때 둘 중 정확히 하나가 주어져야 한다.
- 두 방식이 쓰는 룰 파일은 저장소 최상위 `rules/`로 옮기고, 루트가 읽어 두 모듈에 같은 내용을 넘긴다.

## 근거

- **두 방식을 동시에 띄울 이유가 없다.** 비교는 같은 요청을 방식마다 따로 보내 측정한다. 관리형 엔드포인트는 경로가 연결되지 않아도 시간당 과금되므로, 함께 띄우면 직접 운영 방식을 측정하는 동안 비용만 나간다(`NFR-04`).
- **방식 선택과 경로 전환은 목적이 다르다.** 방식 선택은 무엇을 만들지, 경로 전환은 언제 트래픽을 보낼지를 정한다. 경로 전환을 따로 두어야 두 방식 모두 「먼저 만들고 확인한 뒤 경로를 켠다」는 순서를 지킬 수 있다(`ADR-024`).
- **경로 타깃 인자를 AWS의 인자 이름대로 받는다.** 타깃의 종류를 문자열로 받아 분기하는 것보다 코드를 읽는 사람이 무엇이 어디로 가는지 바로 알 수 있다.
- **룰 파일을 루트가 넘기면 공유가 코드에 드러난다.** 한 모듈이 다른 모듈 폴더의 파일을 읽는 구조는 공유 사실이 숨겨지고, 한쪽 모듈을 옮기거나 지울 때 다른 쪽이 깨진다(`ADR-022`).

## 고려한 대안

**두 방식을 함께 배포하고 경로만 전환** — 방식을 바꿀 때 다시 만들 필요가 없어 전환이 빠르다. 관리형 엔드포인트의 시간당 요금이 직접 운영 측정 내내 발생한다.

**방식 선택 값 하나로 경로 전환까지 결정** — 변수가 하나로 줄어든다. 새 방식을 만들면서 바로 경로가 넘어가 `ADR-024`의 두 단계 적용이 성립하지 않는다.

**타깃 종류와 식별자를 하나의 객체로 받기** — 입력이 하나로 줄어든다. 종류 문자열을 모듈이 다시 해석해야 하고, 경로 인자와 대응 관계가 코드에 직접 드러나지 않는다.

## 결과

- 방식을 바꾸려면 기존 방식의 리소스를 지우고 새로 만든다. 관리형은 생성과 삭제에 각각 5분 안팎이 걸린다.
- 방식 선택 값을 바꾸면서 경로를 켠 채로 적용하면 경로가 새 타깃을 기다리는 동안 트래픽이 끊긴다. 방식을 바꿀 때는 경로를 끈 상태에서 바꾼다.
- 모듈 주소가 `module.firewall`에서 `module.firewall_managed[0]`으로 바뀌었다. 배포된 상태가 없는 시점에 바꿨으므로 상태 이동은 필요 없었다.
